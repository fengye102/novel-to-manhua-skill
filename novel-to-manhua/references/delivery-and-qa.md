# 交付与质检

## 新作品目录

在新项目的 `Codex.md` 中确认实际目录约定。缺省可用：

```text
comic-project/
├── Codex.md                 # 范围、风格、命名、版本与清理规则
├── source/                  # 小说原文与用户提供的原始素材；不覆盖
├── planning/
│   ├── story-map.md          # 情节节点、原文出处、改编取舍
│   ├── visual-bible.md       # 角色版本、场景、配色与风格锚点
│   └── page-script.md        # 页/格脚本、准确台词、文字位置
├── drafts/                  # 中间图、提示词和返工记录；按页命名
├── pages/                   # 最终页：cover-00.png、page-01.png...
└── qa/report.md             # 页级验收结果及待修问题
```

只创建本次实际需要的目录。若用户已有项目结构，遵循其 `Codex.md`。原文、已确认角色参考和最终页不可因清理草稿而误删。版本号写在草稿文件名或返工记录中，`pages/` 只放当前验收通过的成品。

## 页级脚本最小字段

```text
页码 / 对应原文 / 本页推进点 / 结尾翻页点
第 N 格：位置与景别；角色版本；可见动作与表情；环境/道具；
        旁白、对白、拟声词的准确文字与说话者；文字安全区；衔接上一格的方法。
```

若原文有含糊之处，可在 `story-map.md` 标注“改编推断”；不要把推断冒充原文事实。对人物行为动机的增删需能从原文找到依据。

## 出图前后核对

1. **剧情**：每页有推进；重要起因和结果都出现；没有突兀的因果跳跃、重复页或错位页。
2. **角色**：逐项对照选定的[人物视觉卡](character-cards.md)；脸、眼型、发型、服装版本、道具与上一页一致；视角变化不改变身份。黑色细线四肢与圆球手连在正确人物上，能完成画格动作，不悬空、不穿脸、不多出黑点。
3. **画格**：手机缩略图中先看得懂动作与情绪；格间阅读顺序明确；大场景与特写有变化；对白尾巴指向正确人物。
4. **中文**：标题、人名、称谓、台词、标点和页码逐字对照脚本；不保留乱码、缺字、错别字、模型自造台词或难辨小字。
5. **版式**：正文漫画主体按目标长宽比导出，不烘焙手机状态栏、导航条、灰色外框或截图水印；文字框不遮挡眼睛、手势、关键道具。以约 360 px 显示宽度检查一遍。
6. **整套**：文件数量、页码、封面、结尾钩子和引用素材齐全；风格与光线连续。只有通过的页面进入 `pages/`，待修页保留在 `drafts/`。

## 最终回应

报告完成的封面/页数、作品覆盖的原文范围、最终文件夹位置、尚未解决的质检项。若只完成脚本或样张，明确标明，不将其称为整套完成。
